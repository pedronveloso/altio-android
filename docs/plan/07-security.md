# 07 — Security

## Threat Model

Even though the server binds only to loopback, any app on the device can reach it. We treat local callers as potentially untrusted and enforce explicit identity per client.

| Threat | Mitigation |
|--------|-----------|
| Unauthorized app accesses the server | Bearer token required on every request |
| One app reads another app's conversation | Sessions are scoped to the bearer token's `clientId` |
| Malformed input crashes the server | Input validation + `StatusPages` catch-all |
| Large audio file causes OOM | Request size limit enforced before body is read |
| Runaway client monopolizes inference | Per-token concurrency and session caps |
| Server exposed to LAN | Bind address hardcoded to `127.0.0.1` |

## Bearer Token Model

### Token Generation

Tokens are generated by the server on first setup and stored in DataStore (encrypted with `EncryptedSharedPreferences`-style protection via Android Keystore).

```kotlin
fun generateToken(): String {
    val bytes = ByteArray(32)
    SecureRandom().nextBytes(bytes)
    return bytes.toBase64Url()  // 43-character URL-safe base64 string
}
```

### Client Registration Flow (v1 — manual)

1. User opens the host app and navigates to **Settings → Client Tokens**
2. Taps **Generate Token**
3. Copies the token and pastes it into the client app's configuration
4. Client app sends `Authorization: Bearer <token>` on every request

Future versions may automate this via a QR code or Android-to-Android secure channel.

### Token Storage (server side)

Room table `client_tokens`:

```kotlin
@Entity(tableName = "client_tokens")
data class ClientTokenEntity(
    @PrimaryKey val tokenHash: String,   // SHA-256 of the raw token (never store raw)
    val clientId: String,                // "client_<uuid>"
    val label: String,                   // Human label e.g. "My Demo App"
    val createdAt: Long,
    val lastUsedAt: Long?,
    val isRevoked: Boolean,
)
```

Validation in the auth middleware:

```kotlin
suspend fun validateToken(raw: String): ClientPrincipal? {
    val hash = sha256Hex(raw)
    val entity = tokenDao.findByHash(hash) ?: return null
    if (entity.isRevoked) return null
    tokenDao.updateLastUsed(hash, System.currentTimeMillis())
    return ClientPrincipal(entity.clientId, entity.label)
}
```

## Session Scoping

Every session and job stores `clientId`. Handlers enforce ownership:

```kotlin
fun ApplicationCall.requireOwnership(session: Session) {
    val principal = principal<ClientPrincipal>()!!
    if (session.clientId != principal.clientId) {
        throw AiServiceException(HttpStatusCode.Forbidden.value, "SESSION_NOT_FOUND")
    }
}
```

Note: returns `SESSION_NOT_FOUND` (not `FORBIDDEN`) deliberately — clients should not be able to enumerate other clients' session IDs.

## Input Validation

### Request Size Limit

Enforced globally in Ktor before any handler runs:

```kotlin
install(MaxBodySize) {
    maxBodySize = 30 * 1024 * 1024  // 30 MB (audio upload ceiling)
}
```

For non-audio endpoints a stricter limit is applied per-route:

```kotlin
post("/sessions/{id}/generate") {
    if (call.request.contentLength() ?: 0 > 1 * 1024 * 1024) {
        throw AiServiceException(HttpStatusCode.PayloadTooLarge.value, "REQUEST_TOO_LARGE")
    }
    generateHandler.submit(call)
}
```

### JSON Field Validation

```kotlin
@Serializable
data class GenerateRequest(
    val messages: List<MessageDto>,
    val stream: Boolean = false,
) {
    init {
        require(messages.isNotEmpty()) { "messages must not be empty" }
        require(messages.size <= 100) { "messages exceeds limit of 100" }
    }
}
```

### Audio Validation (in `TranscribeHandler`)

```kotlin
val part = call.receiveMultipart().readPart() as? PartData.FileItem
    ?: throw AiServiceException(400, "INVALID_INPUT", "Expected multipart file")

val contentType = part.contentType
if (contentType != ContentType.Audio.MPEG) {
    throw AiServiceException(415, "UNSUPPORTED_FORMAT", "Only audio/mpeg accepted")
}

val bytes = part.streamProvider().readBytes()
if (bytes.size > 25 * 1024 * 1024) {
    throw AiServiceException(413, "REQUEST_TOO_LARGE", "Audio file exceeds 25 MB")
}
// Duration checked after LiteRT decodes: if > 5 min, reject with INVALID_INPUT
```

## Rate & Concurrency Limits

Enforced in HTTP handlers before touching the scheduler:

```kotlin
suspend fun enforceRateLimits(clientId: String) {
    val activeJobs = jobRepo.countActiveJobsByClient(clientId)
    if (activeJobs >= 5) throw AiServiceException(429, "RATE_LIMITED", "Max 5 concurrent jobs")

    val sessionCount = sessionRepo.countByClient(clientId)
    if (sessionCount >= 20) throw AiServiceException(429, "RATE_LIMITED", "Max 20 sessions")
}
```

No token-bucket rate limiter in v1 (request frequency is naturally limited by inference time).

## Loopback Enforcement

The bind address is set to `127.0.0.1` in `AiHttpServer`. A unit test verifies:

```kotlin
@Test
fun `server does not accept connections on non-loopback address`() {
    val server = buildTestServer()
    server.start()
    val port = server.port.value!!

    // Loopback should work
    Socket("127.0.0.1", port).use { it.isConnected shouldBe true }

    // LAN address should not (kernel rejects before the server sees it)
    assertThrows<ConnectException> {
        Socket(InetAddress.getLocalHost(), port).apply {
            if (InetAddress.getLocalHost().isLoopbackAddress) return@assertThrows
            use { }
        }
    }
    server.stop()
}
```

## HTTPS Consideration

v1 does not use TLS because:
- Loopback traffic does not leave the device
- Self-signed certs require client-side trust configuration which adds friction
- Android prevents MitM on loopback

If a future version needs network exposure (e.g., USB tethering to a dev machine), TLS with certificate pinning should be added at that point.
